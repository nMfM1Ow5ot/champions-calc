ポケモンチャンピオンズ ダメージ計算アプリ 使い方メモ
================================================

■ 起動方法 (Mac)
ターミナルでこのフォルダを開き、次を1つ実行するだけ (UI サーバと
画面リーダーが両方起動し、ブラウザも自動で開く。終了は Ctrl+C で両方止まる)
     bash start_all.sh
   - 初回は「画面収録」の許可が必要 (システム設定 → プライバシーと
     セキュリティ → 画面収録 でターミナルを許可)
   - iPad を USB 接続し、QuickTime Player の「新規ムービー収録」で
     入力を iPad に切り替えて画面を表示しておくこと
   - UI だけ / リーダーだけを起動したい場合は start_ui.sh /
     run_reader.sh が従来どおり使える

■ 画面の見方
・上段が自分、下段が相手のパネルで、表示は 1 体 vs 1 体 (本家 Showdex と
  同じ)。表示中の 2 体同士でダメージを計算する
・各パネル上部のアイコン行がパーティ。クリックで表示するポケモンを
  切り替える。場に出ている 2 体はアイコンが青く光り、選択中は白い輪が
  付く。reader が対戦画面を読むと、表示は場の先頭ポケモンへ自動で移る
・相手の型は初期状態では pokedb の使用率トップ型 (現在のレギュレーション)
  を仮定している。対戦中に技・持ち物・特性が判明したら、その項目だけ
  実測値に自動で訂正される (state.json の revealed 情報)

■ 主な操作 (Showdex と同じ操作感)
・プルダウン (特性 / 性格 / 持ち物 / 技 / 相手の種族名 / 天気 /
  フィールド / セット): クリックで開き、文字を入力すると候補が絞られる。
  ↑↓キーで移動、Enter で決定、Esc で閉じる。選択中の項目は青く表示される
・プルダウンの ✕: その項目を空にする (技は「(技なし)」、持ち物は「なし」)
・相手パネルで手動訂正した項目は、プルダウンが青くハイライトされる
・EV の値: クリックすればそのまま書き換えられる。↑↓キーで ±1、
  Shift+↑↓ で ±4。EV 欄の見出しに残り (↓) や超過 (↑、オレンジ) が出る
・ダメージ数値: クリックで結果テキストをコピー
・HP (%): 数値をクリックして書き換え。0% にすると「RIP」(ひんし) 表示
・状態異常: HP の横のバッジ (OK / BRN など) をクリックして選ぶ
・ランク: − / + ボタンで変更
・天気 / フィールド / 壁・おいかぜ等: 中央のチップとプルダウンで設定
・メガシンカ: 技ボックス見出しの「メガ」チップで切替 (アイコンもメガ後に
  なる)。「CRIT」チップはそのポケモンの技を全て急所として計算する
・セット欄の「読み込み / 書き出し / すべて」: Showdown 形式の
  テキストでセットをコピペできる (EV は SPs: 行として読み書きする)

■ 対戦中の reader の動き
・画面の取得は 1 秒に 1 回。ターミナルには Showdown 形式のバトルログ
  だけが流れる (同じ内容が battle.log にも保存される)。ダメ計への
  反映はすべてこのログ経由で行われる
・選出画面が映ると、相手チームは自動でリセットされたうえで、選出画面の
  パネルから相手 6 体の推定が始まる (少し待つと自動で実行される)。
  タイプアイコンで候補を絞り、表示モデルと照合して同定する。同定した
  6 体はログの |poke| 行として表示される
・タイプだけで確定する枠と照合の差が大きい枠はそのまま登録される。
  際どい枠は 1 位を仮置きする。仮置きが違っていたら、種族名の
  プルダウンで手動で直せる。対戦が始まればプレートの読み取りで
  順次確定していく
・でんきタイプのアイコンだけはまだテンプレート未登録のため、その枠は
  推定が外れやすい (でんきを含む相手が映ったスクショがあれば Muse に
  送ると登録できる)
・対戦画面のプレートから、登場・交代 (|switch|)、HP の増減
  (|-damage| / |-heal|)、ひんし (|faint|) を自動でログに起こす
・状態異常・相手の使った技・持ち物・特性・ランク変化・天候は、
  ゲームの「ログを見る」画面を開くと取り込まれてダメ計に反映される
  (毒などの状態異常はプレートに出ないため、この画面が情報源)。
  一度取り込めば画面を閉じても保持される。フィールド (グラス
  フィールド等) と天候はこの画面のヘッダーからも反映されるほか、
  あめごい・にほんばれ等の技を使った記録からも自動で付く。
  「様子を見る」画面上部のフィールド状態バーからも拾う
・マッチング中・演出中・メニュー画面など、対戦画面でない間はエラーに
  ならず静かに待機する (最後の状態を保持)

■ 自チームの登録
・UI 上部の「能力画面を撮影」「ステータス画面を撮影」ボタンを使う
  (リーダー起動中に、ゲームのチーム確認画面を QuickTime に映して押す)
・能力タブとステータスタブを 1 回ずつ撮影すると my_team.json に
  6 体分が登録され、次回起動時から自分のチームとして読み込まれる
・能力ポイント (EV) と性格は、ステータス実数値から自動で逆算される

■ 試合ログの備考と送信
・試合が終わると、start_all.sh / start_ui.sh を実行している
  ターミナルに「備考 (空欄で Enter = 備考なしで送信):」という
  入力プロンプトが出る。その試合のログは、ここで入力が済むまで
  送信されない (送信待ちの間は Mac の logs/ に保存されているだけ)
・備考は 1 行で入力する。気になった場面や直してほしい点、分析への
  指示などを自由に書ける。書くことがなければ、そのまま Enter を
  押せば備考なしで送信される
・プロンプトが出ていないときに送りたい場合は、別のターミナルで
  このフォルダに移動して
    python3 serve.py --note
  を実行すると、送信待ちの試合を順に聞かれる
・備考はログと一緒にログ分析チャットへ届き、内容に応じて
  champions_calc 全般 (reader / UI / 計算 / 型推定など) の修正の
  手がかりになる

■ データの更新 (レギュレーション変更時)
・相手の想定型データは data/regulation.json の設定で管理している
・新しいレギュレーションが始まったら:
  1. pokedb (champs.pokedb.tokyo) で新しい rule 番号を確認
  2. data/regulation.json の "rule" をその番号に書き換える
  3. bash update_data.sh を実行する
     (シーズンとレギュレーション名は自動検出され、使用率トップ型と
      チャンピオンズ実装済みリストが再生成される)
・update_data.sh には Node.js が必要。実行が難しければ、Muse に
  「新しいレギュレーションのデータに更新して」と頼めばよい

■ 選択肢について
・ポケモン / 持ち物 / 技の候補は、現時点でチャンピオンズに実装されて
  いるものだけが表示される (data/champions_dex.json)
・候補にない名前でも、直接入力すれば計算データにあるものは使える

■ 困ったとき
・state.json がないというエラーがターミナルに出続ける場合:
  start_ui.sh はログを出さない専用サーバ (serve.py) を使う版に
  なっているか確認する (古い zip の場合は新しい zip に入れ替える)
・リーダーがコンパイルエラーになる場合: エラーメッセージをそのまま
  Muse に送ればよい
・チーム画面の取り込みだけをターミナルで試す場合: チーム確認画面を
  表示して、ステータス タブなら
    bash run_reader.sh --team-screen status
  能力タブなら
    bash run_reader.sh --team-screen ability
  を実行すると、カードごとに何が読めたか表示される。うまく読めない
  カードがあれば、その出力をそのまま Muse に送ればよい
・画面が崩れる場合: ブラウザのウィンドウが極端に小さいと全体が
  スクロール表示になる (重なったり見切れたりはしない設計)
・選出画面の相手推定がおかしい場合: 選出画面を表示したまま
    bash run_reader.sh --debug
  を実行すると、取り込んだ画面が debug/frame.png に保存され、
  パネルの実測値とタイプアイコンの判定スコアが表示される。
  その表示と debug/frame.png を Muse に送ればよい
・バトルログに技や状態異常が取り込まれない場合: 「ログを見る」の
  画面を表示したまま
    bash run_reader.sh --debug
  を実行すると、ターン検出・チップ・本文の読み取り結果が表示される。
  その表示と debug/frame.png を Muse に送ればよい
・対戦中のメッセージ (技・特性・持ち物の判明、天候/フィールド、
  状態異常、勝敗や降参) は画面下のメッセージ文からも自動で
  ログ化される。うまく拾えていない文があれば、その場面の
  スクリーンショットを Muse に送ればよい
・ファイルは自動更新される: sync_ui.py 自身と state.json・team_key.txt を
  除くほぼ全ファイル (reader.swift や data 一式を含む) は
  起動時と 5 秒ごとにオンライン (GitHub) から自動で最新版に同期される。
  同期は変わったファイルだけを落とす方式なので、通常は数秒で反映される。
  開いている画面も自動で再読み込みされるので、UI の修正を受け取るのに
  新しい zip をダウンロードする必要はない。
  reader.swift が更新された場合は、次の対戦の選出画面でリーダーが
  自動で再起動して新しい版になる (対戦中は再起動しない)。
  オフライン時は手元のファイルがそのまま使われる。
  my_team.json (登録した自チーム) も同期対象で、オンライン側が正本になる。
  ただしチームの中身は暗号化して置いてある (リポジトリでは my_team.enc)。
  復号に使う team_key.txt が同じフォルダに必要なので消さないこと。
  チームを変えたいときは Muse に伝えること (reader でローカル登録した
  チームは同期で上書きされる)。state.json は同期対象外。
