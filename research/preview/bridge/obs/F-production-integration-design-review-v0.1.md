## Critical findings
C-01 — identity and boundary semantics (FI-02/03). Design submits before OCR yet session epoch may change on OCR scene transition. reader.swift 535–571 drops sleep-resume/near-identical frames; 10828–10888 detectPreview has side effects and reappearance resets. A first frame sent under old session may be rejected after epoch advances (safe but lost); accepting by current epoch would instead risk cross-session contamination. Split immutable acquisition generation/frame ID from semantic session binding; specify exact decision point, monotonic deadlines and authoritative state queue; result eligibility must reference one immutable frame record, bind to session only on verified transition, prohibit retroactive relabeling or application after boundary. Define replay/one-shot/debug/team-mode behavior and capture invalidation, dropped frames, no distinct-vote from identical frame. Acceptance tests: first preview, OCR miss/reappearance, cancel/rematch, sleep/resume, reordered/late result, duplicate, source restart; zero cross-session application and explicit accounting.
C-02 — rollback/retraction and state authority (FI-03). reader.swift 11165–11243 compacts opponent slots, marks oppUnconfirmed, publishes oppReset/oppTeam and can reset log after failed attempts; updateOppTeam 1070ff replaces provisional slots by observed species. ui.html 3923ff resets inference on oppReset; 3984ff filters nulls, ignores empty array and subset in reset-pending state, otherwise updates team context. Counterexample: wrong F candidate published, child fails, reader retains observed subset or stops writing; UI can retain unverified team and inference. F held/error cannot be passed to existing identifyPreview failure/reset path. Define explicit session state machine and candidate revisions, ownership of observed vs provisional vs user corrections, invalidation/retraction with consumer recomputation and acknowledgments or demonstrably equivalent mechanism; no confirmed events or own state loss. Existing provisional status not sufficient. Keep shadow outputs entirely outside old state. F publishing blocked until tests for partial/empty/withdrawn team, duplicate species clause, conflict/corrections, active battle, repeated reset, failure before/after commit. No implicit extension of UI schema approved here.
C-03 — release compatibility across sync (FI-04). Frozen Python release alone cannot freeze Swift/serve/UI/data; existing start_all invokes sync_ui.py --force || true; serve self-repair fetches manifest/raw main and self-restarts; reader maybeRestartForUpdate 10816ff guards previewHandled, not explicitly active battle. Design requires safe boundaries but lacks exact atomic transaction and compatibility handshake for all participants. Specify release set identity and immutable staged dependencies, local sync bootstrap/read-only inventory, no mixed set activation, no background repair inside experiment, rollback to coherent previous set, active-battle/no pending event guard, startup preflight before any kill/sync. Verify interrupted update, mismatched reader/worker, offline stale manifest, self-restart, old local launcher, active battle. Never invoke unmodified start_all in isolation. Production integration blocked pending local sync inspection and mechanism proof.
C-04 — pre-registered production acceptance (FI-03/04). Independent admission 0; 7/7 images overlap, all normal path, exact label denominator 1, no negative cohort. 659 regression equivalence is not accuracy. Define target population/input profile, sample unit (battle/recording cluster, not slot/frame independence), positives/negatives, full/fallback, exact/base and held denominators; pre-register risk/coverage and latency thresholds, required sample/evidence and uncertainty, stop rule, failure/hold policy, separately approved before independent evaluation. No invented numeric accuracy target or sample count; use resource and decision-risk tradeoff. If insufficient independent assets, f remains disabled, shadow may remain candidate-only. Prior seven-image results not reused as holdout.
## Important findings
I-01 — IPC executable contract/resource bounds (FI-02). 4-byte framing promising; exact ready/request/response/error field schema, integer bounds, Unicode/duplicate JSON keys, timeout starts at admission vs write, write/read cancellation, independent watchdog and stderr drain must be specified; monotonic capture vs queue vs round-trip measured separately. A blocking pipe write or PNG encoding can stall despite read timeout. EOF not sufficient for native hang/parent crash; close FDs, owned-process reap and bounded escalation, parent death detection/host proof, no arbitrary PID kill. Queue 1+1 must include encoded/in-flight copies and pending diagnostics, cap memory/disk and log rate. Provisional 250ms round-trip and 10s ready not validated; define hard deadline vs p95 separately. Mock hostile/truncated/oversized/late frames, partial writes, worker crash/hang, stderr flood and cancellation, check no deadlock or orphan. Required before real worker shadow.
I-02 — mapping/coverage and legality (FI-03). Unique names_index IDs 1323, types keys 370 do not imply coverage of 293 private IDs or M-C registration legality. Exact-ID mapping with aliases, species-clause groups, form distinctions, no fuzzy base normalization; record unknown/illegal/ambiguous and unsupported legal forms, audit against frozen M-C Showdown validator and local master. Individual eligibility is not team legality; verify candidate combinations only where appropriate, do not infer hidden moves/items/SP from preview. Top5 truncation may exclude legal true candidate; don't renormalize scores, force replacement or claim exhaustive support. Require full mapping disposition and coverage denominator, not necessarily all mapped if unavailable; hold unsupported slots. Block real mapping output used for state until audit complete.
I-03 — temporal corroboration and capture compatibility (FI-01/03). Two distinct frames can share systematic error, adjacent frames highly correlated; agreement is not independent confirmation. Separate identity dedup and acceptance evidence; no hard lock on repeated F guesses. QuickTime capture is existing source; PV11 fallback exactly 1920x1080, OBS research not equivalence. Profile input dimensions/crop/color/orientation using existing recordings/assets with known provenance, no arbitrary resize, report unsupported route and scene OCR misses. Negative scene classification separate from held. Distinguish F kernel, encoding, queue, OCR, decision and end-to-end times; account for all frames including skip/drop/timeout, replay parity and no change to legacy observable behavior except explicitly normalized timing. Calibration immutable and not fitted on holdout. Block real profile rollout until evidence.
I-04 — isolation/privacy/restore (FI-04). serve.py 632–688 uploads battle logs, states, observations, debug images/JSON; naming convention alone insufficient. Research diagnostics outside served/uploaded directories, private permissions, bounded retention and no raw image paths/labels export, no network/port 8765, verify no writes outside allowlist; test with existing service running using mocks/isolated ports only, no original startup. Legacy backup 991 regular files/static pass; actual runtime dependency restore and 171 Apple metadata excluded. Check exact host dependency versions, local sync script, venv/permissions, approved ongoing reference bank/calibration use. Seven-image local-reference authorization not blanket runtime authorization. No need to upload backup or private assets. Isolated runtime restore before deployment, not necessarily before mock protocol work.
