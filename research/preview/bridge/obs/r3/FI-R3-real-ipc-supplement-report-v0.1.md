## Boundary contract (conservative)
For every decoded eligible frame create immutable acquisition A before OCR. If that frame establishes a new semantic session S, invalidate any old apply tokens and all outstanding A from previous semantic generation, including the transition-triggering A. Do not rebind, resend as new evidence, or consume that frame in f. Shadow may record its outcome with transition disposition only. First eligible subsequent frame must be captured after established boundary, source/profile/generation unchanged, independently verified phase and no intervening invalidation; bind once on state queue to current S. Ambiguous boundary suspends candidate application and withdraws published hypotheses if provenance invalid; preserve confirmed observations/user corrections. F gate never establishes S. Trusted boundary detector still requires actual reader state-machine review/replay; conservative rule may reduce coverage and is not approved as production threshold.
## Snapshot digest and acknowledgment proposal
For future candidate-only snapshot protocol, use canonical ASCII JSON subset with fixed versioned keys; UTF-8 bytes, no BOM/whitespace, keys sorted by ASCII ordinal, arrays ordered, integers represented as canonical unsigned decimal strings, booleans/null explicit, strings restricted to manifest-validated ASCII ID/UUID/digest/enum tokens; references opaque ASCII IDs, not user text. Reject extra/duplicate keys, invalid types, noncanonical encodings; do not include floating scores or arbitrary Unicode in this canonical subset. Hash exact canonical bytes excluding active_revision_digest, SHA-256 lowercase hex. Full snapshot including hash transmitted with release_set_id, launch/session identity, revision/supersedes and six ordered slots, provenance, disposition, observed/user refs. Acknowledgment carries same release/session/revision/digest plus fresh consumer instance UUID and outcome applied/retracted/unavailable; verify exact outstanding identity, duplicate identical ack idempotent, stale/foreign ack ignored, conflicting ack faults candidate channel. Consumer accepts only verified canonical snapshot from approved current producer, atomically replaces soft candidate layer, recomputes from preserved confirmed facts, acknowledges after completion; absent valid renewal/ack, expire candidate layer and output unavailable, not stale hard facts. Lease renewals carry same snapshot identity and strictly increasing renewal sequence bound to consumer instance; a new consumer starts empty and requires fresh verified handshake and snapshot, not replay of old lease. Consumer TTL local monotonic clock starts on valid receipt, no comparison of cross-process wall clocks; expired lease cannot be revived by late renewal, fresh handshake/current revision required. Producer uses independent monotonic ack deadline and invalidates on loss; no assumption that sending withdrawal alone clears UI. Ack/lease transport, crash/restart, canonical hash parity and actual UI recomputation still require real consumer mock and then actual verification. No production numerical TTL/ack timeout chosen. Mock proposal only: ack deadline 250 ms, renewal interval 250 ms, TTL 1000 ms; verify scheduling/latency and safety tradeoffs before adopting. These constants untested in this run.
