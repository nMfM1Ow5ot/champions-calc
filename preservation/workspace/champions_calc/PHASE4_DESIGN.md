# フェーズ4 (ターン側) 設計メモ — ターン番号の二重化

作成: 2026-11-22、バックエンドチャット。対象 reader.swift (build 20261122_1218 時点)。

## 棚卸し: ターン行の発生源は3つ

1. コマンドフェーズ検出 (processPlates 後段): 全プレートが揃って確定すると
   currentTurn += 1 して |turn| を出す。commandPhaseSeen がラッチで、
   |move| / |switch| / |faint| 行が出るたびに emitLog 側で解除される。
2. ログ画面 (parseLogScreen): ゲーム内ログの最新ターン見出し tn を読み、
   tn > currentTurn なら currentTurn を tn へ跳ばして |turn|tn を出す
   (無条件の追随。文面系統の現行形)。
3. ターン行ガード (emitLog): ラウンド行から境界の取りこぼしを推定して
   |turn|currentTurn+1 を挿入する (規則 a/b/c)。挿入時は
   suppressNextDetectorTurn で検出側の二重出力を抑止する。

## +1 の発生機序 (battle_20261122_091721、デバッグ記録で確定)

- debug02: ターン行ガードが turn 1 を inserted_turn_line で挿入。
  きっかけ行は |-unboost|p1a: Politoed|atk|1 (開幕の いかく の低下行)。
- ガードの規則「currentTurn == 0 かつ roundEventSeen == false なら
  guardN = 1」は、ラウンド行の初出で発火する。isRoundEventLine は
  -unboost / -boost / -sidestart / -damage 等、開幕の入場効果で普通に
  出る行を含むため、開幕区間で必ず先に発火してしまう。
- その後にコマンドフェーズ検出が正規の第1フェーズで currentTurn を
  2 に進めるため、以後全ターンが +1 になる (実像6ターン vs 配信7ターン)。
- debug05/09/10 の後続の挿入 (turn 3/4/5) は検出が働かなかった境界での
  正規の補完だが、初期の +1 を引き継いだ。

## 設計

1. **ターン0のガードは技行だけに限定する**: currentTurn == 0 では、
   |move| 行の初出だけが guardN = 1 を生む。入場効果のラウンド行は
   ターン開始の証拠にならない (技行は解決フェーズの開始を意味する
   ため、検出が第1フェーズを取りこぼした場合の補完として残す)。
2. **検出の即時経路に静穏条件を追加する**: プレート確定による即時発火
   (allSettled 経路) は、最後のラウンド行から 2.5 秒以上の静穏を必須に
   する。解決フェーズの合間 (commandPhaseSeen が最初の行動行で解除
   された直後) の一瞬の揃いで誤発火する経路を閉じる。生フレーム経路
   (6フレーム連続 ≒ 3 秒) は従来どおり。lastRoundEventAt を emitLog の
   ラウンド行処理で更新する。
3. **ログ画面系統を照合として使う**: tn > currentTurn の追随 (取りこぼし
   回復) は維持しつつ、どちらの方向の不一致も turn_disagree の証拠記録を
   残す。tn < currentTurn は番号を戻さない (出力済みの行は変えられない)
   が、証拠が残ることで次戦以降の切り分けができる。ただし
   tn == currentTurn - 1 かつ今ターン未行動 (roundEventSeen == false)
   の場合は、コマンドフェーズ中にログ画面の見出しがまだ無いだけの
   正常な遅れとして記録しない。

検証: ハーネスで開幕列 (交代行 → いかく低下行 → 技行) を再現し、
ターン行が技行の直前に 1 本だけ出ることを固定する (T131)。実戦での
再測定は、次に開幕入場効果のある試合が golden に追加された時点で行う
(フェーズ1の枠組み)。
