# MH-001-MATH — 数学的検証報告書

- 対象: 複数ヒット技のダメージ乱数分布（MH-001）
- 前提の区別: 本書の「正しさ」は、独立乱数モデルの下での数学的正しさを指す。各ヒットの乱数の独立性は、本家シリーズの文書化された仕様に基づく仮定であり、Pokémon Champions 固有の公式確認は得られていない（MH-001-REPORT.md §4・§11）。

## 1. 修正前の計算方法の数学的意味

修正前の処理は、ヒットごとの乱数配列を同じ添字同士で加算していた。乱数配列の添字は乱数値の小さい順（0.85 倍〜1.00 倍）に対応するため、この加算が表すのは、全ヒットが常に同じ乱数値を取るという、完全な正の相関（コモノトニック結合）の下での合計分布である。

この結合の下では：
- 合計の取り得る値は最大で16通りに限られ、独立の場合に到達可能な中間の値（例：21、23、25）が欠落する。
- 最小値（全ヒット最小の和）、最大値（全ヒット最大の和）、平均（各ヒットの平均の和）は、独立の場合と一致する。このため範囲表示と期待値は正しく見え、欠陥は確率質量の配分にだけ現れる。
- 観測が欠落した値に一致した場合、その候補の尤度は0になり、誤排除の原因になる。

## 2. 修正後の確率分布の定義

各ヒット i のダメージを確率変数 X_i とし、ヒット数を n（計算に用いた回数に固定）とする。合計ダメージ D = X_1 + … + X_n の分布を、

P(D = d) = Σ_{x_1 + … + x_n = d} Π_i P(X_i = x_i)

で定義する。各 X_i の分布は、ライブラリが返すヒットごとの16本の値の経験分布（各値の頻度／16）である。実装上の表現は整数の組合せ数で、値 d の組合せ数を C(d) とすると P(D = d) = C(d) / 16^n である。

## 3. 畳み込みアルゴリズムの正当性

convolveHitRolls は、分布を「値 → 組合せ数」の Map で保持し、ヒットを1つずつ畳み込む動的計画法である。各段で、新しいヒットの全値との和へ、組合せ数の積を加算する。これは §2 の定義の直接の計算であり、列挙順序に依存しない（加算と乗算の交換・結合性による）。正当性は、T04 における小規模な全列挙（16^n 通りの独立した参照計算）との照合で実証した（2〜5ヒットで全値の組合せ数が一致）。

計算量は、各段で「現在の値の種類数 × 16」に比例する。値の種類数はダメージの取り得る幅で抑えられ（1ヒットの幅が高々16値分）、ヒット数に対して爆発しない。組合せ数の総和は 16^n で、最大の対象（10ヒット）でも 16^10 = 2^40 であり、JavaScript の数値（倍精度）で整数として厳密に表せる範囲（2^53）にある。確率への変換は最後に total で割るため、途中の丸めは発生しない。

## 4. 重複乱数値の処理

同じダメージ値が1ヒットの16本の中に複数回現れる場合、その重複は頻度として保持される（Set 化はしない）。例えば [10, 10, 11, 12] は、10に質量 2/4、11と12に各 1/4 を与える。畳み込みは組合せ数の積で進むため、重複は自動的に正しい重みになる（T02 で検証：20:4、21:4、22:5、23:2、24:1、総数16）。

## 5. 確率正規化の方法

分布は整数の組合せ数のまま保持し、確率が必要な箇所で counts/total を計算する。総和は構成上ちょうど total（= 16^n）であり、正規化後の総和は1である（浮動小数の除算誤差を除く）。尤度の比較に使う場合は質量そのものを用い、候補間の相対比較では total が共通のため組合せ数の比と等価である。

## 6. 候補排除・尤度評価への接続

- 尤度：観測ダメージ d に対する尤度は P(D = d)。区間観測 [lo, hi] に対しては区間内の質量の合計 Σ_{lo ≤ d ≤ hi} P(D = d)。HP 割合の観測に対しては、割合の換算（切り捨て／四捨五入の両対応）で観測値に対応するダメージ値の質量の合計。
- 候補排除（制約交差）：到達可能性は「質量が正の値が条件を満たすこと」で判定する。分布の支持集合が正しいため、真の型が到達不能と判定されることは、モデルの前提（ヒット数と独立性）の下では起こらない。
- KO 確率：残り HP が h のとき、KO 確率は P(D ≥ h)（回復・途中終了を考えない場合）。T06 で検証（T01 の分布、h = 23 で 62.5%）。
- 期待値：E[D] = Σ d・P(D = d)。修正前の要素ごと加算の平均と一致する（§1）が、修正後は分布から直接計算する。
- ベイズ更新への受け渡し：エンジンは質量×16 を従来の「件数」の位置に渡す。単発では質量 = 件数/16 が二進浮動小数で厳密なため、更新の算術は修正前とビット単位で一致する。

## 7. 独立性が成立しない場合の処理

- ヒット間で決定的に決まる変化（ヒット回数に依存するランク変化・持ち物効果）は、ライブラリがヒットごとの周辺分布に織り込むため、その周辺分布の畳み込みは依然として正しい。
- 前のヒットの「結果」に依存する変化（HP 割合で発動する持ち物、ひんしによる終了、命中判定による終了、ヒットごとの急所の独立判定）は、周辺分布だけからは再構成できない。これらは本修正の対応外とし、合計分布は「全ヒットが命中し、結果依存の変化が無い」条件の下での条件付き分布として扱う（MH-001-REPORT.md §11）。
- 分布が得られない場合（計算例外・変化技）は、尤度を割り当てず、その証拠による確率更新と候補排除を保留する。特定の候補だけに任意の尤度を与えることはしない。
- ヒット数が可変の技で回数が指定されていない場合、分布はライブラリ既定の回数への条件付きであり、その前提（assumedHits）を推論ログに記録する。ヒット数分布まで混ぜた無条件の尤度は、本修正では計算しない。

## 8. 計算量・数値精度・適用限界

- 計算量：分布の構築は §3 のとおり小さい。実測（VM）では damageDistribution 1回あたり 0.4〜2ms（calculate 本体を含む）、候補96件分で約30ms（MH-001-TEST-REPORT.md §8）。
- 数値精度：組合せ数は整数演算で厳密。確率化の際の誤差は除算1回分のみ。事後分布の照合では、独立計算との最大誤差が 1e-9 未満であることを確認した。
- 適用限界：ヒット数の上限は実質的に技データの範囲（最大10ヒット級）で、組合せ数の厳密性は 16^10 まで十分に余裕がある。それを超える仮想的なケースでも、値の種類数が幅で抑えられるため計算量は問題にならないが、組合せ数が 2^53 を超える場合は整数の厳密性が失われる（現行の技には存在しない）。
