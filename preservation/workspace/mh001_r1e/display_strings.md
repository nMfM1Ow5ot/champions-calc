# MH-001-R1-E 表示検証で確認した実際の表示文字列（ダメージ計算チャット）

検証方法: tests/ui_harness.mjs に一時プローブを挿入し、実パネル構成で
calcAll → movesBox の描画結果から文字列を抽出（プローブは検証後に除去済み）。
対戦相手はいずれも カビゴン（HP32/防御32）。

## (1) ヒット数不明の可変ヒット技（タネマシンガン、指定なし、ゴリランダー）
- 要約行の標記: （3ヒット想定）
- バルーン冒頭: 「3ヒットと想定して計算しています（実際のヒット数は未観測で、ライブラリ既定の想定です）。仮定：ヒットごとの乱数は独立として計算しています。ヒットごとの急所・命中判定や、途中で相手がひんしになることによる終了は計算に含めていません。この技のダメージは型推定に利用していません。」
- 続いて分布（63: 1.6%, 64: 7%, …）と急所側の分布を表示。要約行は「23.6 – 28.1%」。

## (2) ヒット数指定済み（タネマシンガン、moveSpec=5）
- 要約行の標記: （5ヒット指定）
- バルーン冒頭: 「5ヒットで計算しています（ヒット数は利用者が指定したものです）。仮定：…（以下 (1) と同じ）」
- 要約行は「39.3 – 46.8%」。

## (3) 固定ヒット技（にどげり、マニューラ）
- 要約行の標記: （2ヒット固定）
- バルーン冒頭: 「2ヒットで計算しています（技の固定ヒット数です）。仮定：…（以下 (1) と同じ）」
- 要約行は「24 – 28.5%」。

## (4) おやこあいによる追加ヒット（メガガルーラののしかかり）
- 要約行の標記: （おやこあい2ヒット）
- バルーン冒頭: 「おやこあいにより2ヒットとして計算しています。仮定：…（以下 (1) と同じ）」
- 要約行は「31.1 – 36.7%」。

## (5) 一部候補が計算不能な場合の候補範囲
## (6) 全候補が計算不能な場合の候補範囲
- エンジン側の固定契約により、(5)(6) はどちらもエントリ { unavailable: true } として
  UI に届く（信用集合内に計算不能な候補が1件でもあれば集計値は返らない）。
- UI 表示（ドラゴンクローの行で検証）: 「候補範囲は計算不能のため表示保留」
  （title 属性: 「型候補の中に計算できない候補があるため、候補範囲の集計を表示保留しています」）
- 検証方法: 推定エンジンの candRanges の戻り値を UI 境界で { unavailable: true } に
  差し替えて描画を確認。{ unavailable: true } の生成自体はエンジン側の完了済み作業。

## (7) 有効な分布で真の KO 確率0の候補範囲
- 集計エントリ { lo: 0, hi: 99.9, exp: 0, ko: 0 } を差し替えて検証。
- UI 表示は従来どおり: 「候補 0–99.9%」（表示保留にはならない）。

## (8) 正常な単発技（ドラゴンクロー、ガブリアス）
- バルーンは従来どおり 16 本のロール列＋急所側の併記のみで、
  ヒット数注記・仮定注記は付かない。要約行の標記も付かない（従来どおり）。

## 画面例について
バルーンはパネル全体のレイアウト文脈でのみ正しく描画されるため、切り出した
同等描画では崩れることを確認した。成果物としては上記の実描画文字列を正とする。
